# 抽乌龟 v0.2 · 更新说明及验收记录

更新基础：v0.1，保留原生 HTML、CSS、JavaScript、Node.js HTTP + SSE、内存房间的轻量架构；不引入第三方 npm 包、数据库或 Docker。

## 主要变更

| 功能 | v0.2 行为 | 验收关注点 |
| --- | --- | --- |
| 抽牌动画 | 背面牌从公开的抽牌位置飞向行动玩家；配对后公开两张牌 | 未配对的牌面不能向观众泄露 |
| 最终抽牌 | 先播放动画，再揭晓结算 | 最后一张牌与开局移除牌同点数 |
| 手游手牌排序 | 长按 320ms 生成跟手虚影，悬停时标记目标位，贴近边缘自动滚动 | 普通滑动不卡死，不意外重排 |
| 手游暗牌 | 多张牌先选后确认，单张直接抽取，卡牌超宽时横向滚动 | 横屏 667×375、844×390 可用 |
| AI 主动洗序 | AI 在自己行动阶段非锁定状态随机洗序 | 不允许在被抽牌时改变顺序 |
| AI 有效记忆 | 抽走牌后保留按索引位移推算出的有效信息，追踪合法已知的牌转移 | 洗序/重排后位置记忆清空，配对后受影响的位置清空 |
| 双客户端同步 | 服务器统一执行抽牌、弃牌、回合推进与最终结算 | 真人双方能分别看到各自手牌，不可读取对手暗牌 |
| 样式拆分 | `style.css` 为基础/PC，`mobile.css` 维护手机布局 | 横屏不重叠；竖屏可用，不请求旋转权限 |

## AI 信息边界

- 可使用：自身手牌、公共弃牌、公开抽牌位置、其他玩家手牌数、合法记住的牌位。
- 不可使用：被移除牌的内容、其他玩家当前隐藏手牌、未来洗牌或抽牌结果。
- 只在有可信牌位证据时优先选择能配对的牌；其余未知暗牌在无额外合法线索时等概率抽取。
- 若有人调整手牌顺序，该玩家的已知位置记录失效。若有人抽走牌，其他未移动的已知牌位可按索引更新。配对消除时不推测无法观察的第二张牌的原位置。

## 验收执行

- `npm test`：**16/16 项通过**。
- 规则模拟：2～6 人完整随机对局、25 对牌 + 1 张乌龟牌、双人及多人异常边界。
- 真实服务端双玩家 API：创建、加入、抽牌、房间同步、隐藏手牌隔离、完整结算。
- Chromium 浏览器模拟：1336×820、844×390、667×375、390×844，页面无脚本异常，横屏 UI 无重叠。
- Chromium 双客户端桥接至真实 Node.js 服务端：PC 创建房间、手机加入、AI 补位、真人连续抽牌、手机长按移动手牌，观察抽牌飞行动画，未发现运行时异常。
- 测试环境无法直接让 Chromium 导航至本机 HTTP 地址；浏览器联机操作验收使用桥接 HTTP/轮询状态替代原生连接，原生 SSE 另由 Node.js API 测试覆盖。**此项不是实体手机跨网络验收**。
