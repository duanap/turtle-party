# 游戏大厅、房间与联机规则

**适用版本：** v0.3.0。支持真人、AI 和混合对战，不要求注册账号。

## 1. 大厅三大入口

| 入口 | 行为 |
| --- | --- |
| **快速开始** | 默认 1 真人 + 3 AI，直接进入四人局 |
| **创建房间** | 输入昵称、设置 2～6 人容量，获取六位房间号 |
| **加入房间** | 使用六位房间号与未被占用的昵称加入等待房间 |

**快速开始**是主要行动入口；“玩法与规则”属于辅助入口。游戏不包含真实货币、筹码或下注。

## 2. 房间状态

`LOBBY（等待） → PLAYING（进行中） → FINISHED（结算） → 房主可再来一局`

- **等待中：** 房主可以添加或移除 AI；真人可以通过房间号加入。
- **开始游戏：** 房主主动开始，至少两名参与者（含 AI），无需坐满容量；**满员不自动开局**。
- **进行中：** 新玩家不能加入；已在房间的真人可凭原有效会话恢复。
- **结算后：** 房主可以重新开始一局，不沿用上一局的牌面。

## 3. 权限边界

| 操作 | 房主 | 其他真人 | AI |
| --- | --- | --- | --- |
| 查看房间与公开状态 | ✓ | ✓ | 系统参与者 |
| 添加 / 移除 AI | 等待阶段 ✓ | × | × |
| 开局 / 再来一局 | ✓ | × | × |
| 重排 / 洗序自己的手牌 | 未锁定时 ✓ | 未锁定时 ✓ | 未锁定时依策略 |
| 抽牌 | 到自己回合时 ✓ | 到自己回合时 ✓ | 到自己回合时依策略 |

- 房间号用于**找到房间**，不代表身份或授权。
- 每名真人使用随机会话凭证；昵称不能替代身份验证。
- 主动退出等待房间会移除座位；已开始的对局中主动退出则撤销原会话恢复资格，并由托管维持原有牌局逻辑；必要时转移房主权限。

## 4. 实时通信与重连

- 玩家动作通过 HTTP JSON 接口发送；房间状态通过 **SSE** 推送。
- 浏览器使用支持身份请求头的 `fetch` 流接收 SSE，断开后尝试重连；持续失败时有状态轮询兜底。
- SSE 断开约 **5 秒**后，由托管替真人继续随机抽牌；玩家恢复后重新接管。
- 服务端核对操作身份、回合编号和 `requestId`，避免双击或响应丢失导致**重复抽牌**。
- 服务端只向玩家发送其自己的完整手牌；其他人只收到牌数、公开弃牌与可选背面位置。

## 5. 重启与恢复

- 进行中的房间保存在单机内存和私有快照中，服务重启后尝试恢复**相同房间、座位、手牌和会话身份**。
- 重启时网络连接会断开，游戏暂时进入托管准备阶段，允许原客户端在短暂宽限期内重连。
- 客户端的本地 `localStorage` 保存用于重新识别自己的会话凭证；必须通过 HTTPS 提供网页服务。
- 本地快照不构成多实例同步。**同一份快照只允许一个 Node 进程使用**。

有关 API、快照与安全边界参阅[《技术架构》](技术架构.md)。
