# 抽乌龟 v0.3 · 实体设备与公网验收清单

> 此清单用于部署后**人工实际验收**；以下项目目前均未声称实机通过。建议至少一部 Android Chrome 手机、一部 iPhone Safari 和一台 PC 浏览器。

## 设备和操作

- [ ] Android Chrome：横屏 844×390 及更窄尺寸；点选暗牌、二次确认、单张直接抽取。
- [ ] iPhone Safari：横屏、刘海/安全区域、底部手牌横滑、长按 320ms 后拖动，不出现原生选择/复制菜单。
- [ ] Android/iOS：长按手牌拖到另一张牌位置，服务端确认顺序已经改变。
- [ ] 所有端：普通手指横向滑动只是滚动，不意外改变手牌顺序。
- [ ] 所有端：拖动中对手抽牌导致手牌锁定时，浮动牌正确取消。
- [ ] 竖屏：仍能正常操作，不请求旋转权限、不弹强制横屏提示。
- [ ] 2～6 人：抽牌、配对、双人残局、乌龟揭晓，无被遮挡或误点操作。

## 弱网和会话

- [ ] Android/iOS：Wi-Fi ↔ 4G/5G 切换，连接指示从重连恢复到实时联机。
- [ ] 模拟高时延、短时丢包、关闭移动数据 10 秒，座位和手牌保持不变。
- [ ] 断线超过 5 秒进入托管；重连后由原玩家恢复操作。
- [ ] 抽牌提交后强制断网，再恢复：确认只抽一张，没有重复配对。
- [ ] 后台锁屏 1～3 分钟再返回：自动获取最新房间状态。
- [ ] 在牌局进行中重启 Node 进程：同一浏览器刷新后能恢复原座位和手牌。
- [ ] 房主主动离开后，旧会话不能读取房间；剩余真人接管房主资格。
- [ ] 服务端重启后的恢复不泄露其他人的隐藏手牌。

## 服务器 / 生产配置

- [ ] HTTPS 有效，浏览器无混合内容；HTTP 自动跳 HTTPS。
- [ ] Nginx `proxy_buffering off`，SSE 实时状态可以持续推送。
- [ ] Node.js 只监听 `127.0.0.1`，外网不开放 3000 端口。
- [ ] 使用非 root 的独立 systemd 用户；`rooms.json` 为 0600。
- [ ] Nginx 日志中无会话 token URL；敏感响应头不会被日志明文写入。
- [ ] 429 限流、403 跨站拦截、非法 token 拒绝、请求体过大拒绝。
- [ ] 手动备份/恢复快照；验证损坏文件时服务拒绝静默清空房间。
- [ ] 真实多设备持续游戏和小规模并发压测，记录响应时间、内存和 SSE 断流情况。
