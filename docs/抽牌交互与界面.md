# 抽牌交互与 PC／手机界面规范

**适用版本：** v0.4.0。此文档描述公开亮牌、跨玩家选牌反馈与界面操作。

## 1. 单回合交互

`等待轮次 → 展示目标背面牌 → 选中并同步提牌 → 确认 → 全桌翻牌 → 移入手中 → 配对消除或留牌 → 更新回合`

- 当前玩家及其目标突出显示，其他玩家只观察公开信息。
- 点击或触摸背面牌仅“选中”，允许改选或再次点击取消；即使目标仅剩一张，也按“确认抽取”才提交。
- 被抽者手里对应的正面牌提起，全桌背面牌位同步高亮；此时只有牌的持有者知道牌面。
- 提交后全桌看到同一张牌翻开，再飞入抽牌者手牌；抽牌者能先看到新牌加入，随后才展示配对消除。
- 若配成对子，公开两张正面牌并移到弃牌区；否则新牌加入自己的手牌。
- 牌局结束后展示失败玩家、最终牌及开局移除的牌。

**重要：** 动画是服务端结算后的展示，不能决定随机结果或覆盖规则结果。

## 2. 手牌排列与洗序

| 动作 | PC | 手机 |
| --- | --- | --- |
| 浏览自己的牌 | 底部牌列 / 横向滚动 | 底部横向滑动 |
| 重排自己的牌 | 鼠标拖动调整位置 | 长按约 320 ms 后拖动，放开落位 |
| 一键洗序 | 点击洗序 | 点击洗序 |
| 抽取目标牌 | 点击选中 → 确认 | 触摸选中 → 确认 |
| 目标仅一张 | 选中 → 确认 | 选中 → 确认 |

- 洗序不会改变手牌内容或触发新的配对；它改变的是对手的牌位记忆。
- 当前玩家成为抽牌目标时，其重排与洗序按钮禁用。
- 手机**短滑用于滚动，长按用于排序**，应避免操作冲突。
- 拖拽期间应有被拖牌的跟随预览和落点提示；网络回合变化使牌位锁定时，拖拽要取消。

## 3. PC 布局

- 顶栏：游戏标志、房间与连接状态。
- 上方或牌桌周边：其他玩家的头像、昵称、剩余牌数、行动状态。
- 中央：**当前目标的背面牌列**和抽牌确认区域。
- 底部：**自己的正面手牌**与洗序、重排操作。
- 对手有很多张牌时使用横向滚动，不能通过无上限缩小牌面来强行显示全部。

## 4. 移动端布局

- **手机横屏优先**，不请求屏幕旋转权限，不弹强制旋转提示；竖屏提供可操作的适配布局。
- 参考横屏视口：`844×390`、`740×360`、`667×375`。
- 尽量为背面牌保持不低于 **44 × 44 CSS px** 的独立触摸命中区域。
- 顶栏与对手信息紧凑排列，中央保持抽牌操作空间，自己的牌固定在下方。
- 注意系统安全区域、圆角、刘海以及小高度横屏下的信息重叠。
- 横向滑动手牌不应误触发抽牌或改变顺序。

## 5. 动画与反馈

| 事件 | 反馈 |
| --- | --- |
| 选中背面牌 | 全桌高亮对应牌位，被抽者的对应手牌提起；可改选或取消 |
| 牌位重排 | 顺滑交换、落点提示 |
| 确认抽牌 | 牌先向全桌翻开，再移入抽牌者手牌 |
| 抽到对子 | 对子公开并移至弃牌区 |
| 未形成对子 | 已公开的新牌留在手牌中，可通过后续洗序打乱位置记忆 |
| 安全脱身 | 显示已脱身状态 |
| 进入双人残局 | 突出最后两名玩家 |
| 最后一张乌龟牌 | 翻牌并展示胜负 |

动画应简短且尊重系统降低动态效果设置；不得通过音效或动效提前暗示乌龟牌。

首页规则常显；界面文案使用中文，牌面的一、侍、后、王分别对应标准点数 A、J、Q、K。昵称、房间号及人数标签与对应输入控件同一行，页面主标题和操作按钮居中。

## 沉浸式牌桌迭代

- 首页、等待和对局共用背景节点。创建、加入、设置、牌桌说明和退出确认使用弹窗，支持焦点循环及退出键关闭。
- 二至六人围桌入座，开局保留座位并播放洗牌发牌反馈；公共弃牌区展示最近一对公开牌及累计对数。
- 牌桌、头像、标志、装饰及无字底板直接引用 public/assets 中的 PNG。昵称、号码、牌数、倒计时、按钮文字与真实扑克牌点数由 HTML 渲染，每张牌保持独立元素。
- 音效默认关闭，设置中可开启轻柔提示或减少动态效果，偏好仅保存在本机。转屏结束旧坐标动画，优先显示真实状态。
- 没有重新抠图或把整张参考效果图用作界面。对应关系见[素材接入说明](../public/assets/ASSET-USAGE.md)。
