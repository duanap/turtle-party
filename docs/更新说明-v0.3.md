# 抽乌龟 v0.3 · 弱网恢复、房间持久化与安全加固

基于 v0.2 升级，继续使用原生 HTML/CSS/JS、Node.js HTTP + SSE，不增加第三方 npm 依赖、不使用数据库或 Docker。

## 已实现

| 模块 | v0.3 变更 | 核心约束 |
| --- | --- | --- |
| 实时重连 | 基于 `fetch` 的 SSE 读取，断线指数退避重连；两次失败后启动 4 秒一次的状态轮询 | SSE 与轮询均发送身份请求头；不在 URL 中拼接 token |
| 离线保留 | 页面提示连接状态，断网时保留本地会话，不因瞬时请求失败清空登录信息 | 原会话被撤销或房间确实不存在时才清除 |
| 请求幂等 | 每次操作包含 `requestId`，服务器保留最近 160 条操作指纹；恢复后使用原编号核对 | 双击/丢响应不会多抽一张；相同编号不同参数返回 409 |
| 断线托管 | SSE 断开 5 秒后才启动随机代抽（AI 玩家仍用公平决策）；同一身份重连自动接管 | 玩家手牌不重发、不公开 |
| 异常恢复 | `data/rooms.json` 原子快照，进程重启后恢复房间、身份哈希、手牌、回合、AI 记忆和近期幂等记录 | 房间快照只在服务器本机保存，权限 0600 |
| 启动宽限 | 重启后 5 秒内允许旧浏览器先重连，避免立即自动推进 | 重新启动时为未结束回合重置 30 秒时间窗 |
| 认证 | 24 字节随机会话凭证，仅把 SHA-256 哈希保存在服务端及快照；GET 使用 `Authorization: Bearer` | 不使用 URL 查询参数传递会话凭证 |
| 访问防护 | 同源 Origin 检查、Fetch Metadata 跨站拦截、IP/玩家操作限流、SSE 连接上限、房间上限和 8KB 请求体限制 | 不是 DDoS 防护的替代品 |
| 安全响应 | CSP、禁止 iframe、`nosniff`、`no-referrer`、禁用敏感权限等基础响应头 | HTTPS 必须在反向代理层启用 |
| 部署模板 | Debian/systemd 与 Nginx HTTPS/SSE 反向代理配置 | 仅模板，未在真实云服务器上部署 |

## 验收结果

- `npm test`：**24 / 24 项通过**。
- 规则引擎原有测试保留，新增会话凭证保护、请求操作幂等、房间进程重启恢复、SSE 中断与自动托管、主动离开凭证撤销、快照文件权限与快照损坏拒绝启动、限流等测试。
- 实际 Node HTTP/SSE API：双客户端完整抽牌与结算测试通过，真实 TCP SSE 连接断开后可按预期恢复。
- 浏览器模拟：Chromium 仿真 1336×820 PC、844×390 手机横屏、390×844 竖屏；模拟双浏览器从创建房间到入座/开局、离线提示、重连、服务进程重启后保留会话；模拟触屏长按拖动，并通过服务端快照验证手牌顺序确实变化。无页面脚本异常。
- **测试环境浏览器无法直接访问 loopback 地址**，因此浏览器模拟使用桥接 HTTP 与模拟 SSE 流；原生 SSE 行为另外通过 Node.js TCP 接口测试。不能据此认定实体 Android/iOS 已验收。

## 设计边界和剩余工作

1. **未完成实体手机实机测试。** Android Chrome、iOS Safari、真实 Wi-Fi/4G/5G 切换、后台切换与长时间保活需在部署测试地址后进行。
2. **尚未在公网服务器部署及压测。** 必须先启用 HTTPS、反向代理 SSE 关闭缓冲、专用运行用户、存储目录权限和防火墙；再进行公网与并发验证。
3. 房间状态是单机 JSON 快照，**只支持单 Node 进程**，不能同时启动多个实例共享同一数据目录；不包含数据库备份中心。未收到 HTTP 确认的后台 AI 操作仍可能存在约 70ms 的崩溃丢失窗口；普通用户操作在返回成功前等待快照落盘。
4. 服务器重启后重置当前回合的 30 秒时间窗，但不改变当前回合、手牌及胜负状态。
5. 客户端为可恢复会话使用 `localStorage` 保存会话凭证，仍需遵守 HTTPS、避免第三方脚本和 XSS 风险。
6. 已增设基础请求限流和 CSP，但**尚未完成独立安全审计、互联网抗 DDoS 和高并发性能验证**；不可视作正式生产安全认证。

## 与 v0.2 的兼容

v0.2 没有持久化机制，旧进程中的房间无法通过升级自动迁移。部署 v0.3 后，旧房间需要重新创建；后续 v0.3 内的正常重启才支持快照恢复。
