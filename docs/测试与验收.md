# 测试、验收与已知限制

**适用版本：** v0.3.0。请区分**自动化通过**与**实际手机／公网环境已验收**。

## 1. 自动化测试

项目通过 Node.js 原生测试运行器执行测试：

```bash
npm test
```

现有基线为 **24 项测试通过**，测试文件：

| 文件 | 覆盖方向 |
| --- | --- |
| `tests/engine.test.js` | 发牌、配对、抽牌、AI、公平性、特殊残局 |
| `tests/api.test.js` | 房间、身份、操作、SSE、断线与重复请求 |
| `tests/store.test.js` | 快照序列化、数据完整性、恢复与文件权限 |
| `tests/ui.test.js` | 前端结构与交互相关校验 |

GitHub Actions 在 Node.js **20、22** 上自动执行 `npm test`。运行结果应以对应提交的 CI 页面为准；文档中的 24 项为当前版本基线，而非未来固定数量。

## 2. 已进行的浏览器模拟验证

- PC 页面、`844×390` 手机横屏及 `390×844` 竖屏布局。
- 模拟长按拖动，并核对服务端手牌顺序的实际变化。
- 双客户端房间创建、加入、AI 补位与抽牌同步。
- 弱网连接提示、模拟断开与恢复。
- Node HTTP/SSE 接口层面的完整对局、自动托管和快照重启恢复。

**限制：** 测试环境中的 Chromium 浏览器曾通过 HTTP/SSE 桥接访问本机服务；原生 SSE 另由接口测试确认。**这不等同于实体手机和公网验收。**

## 4. 开发验收标准

修改规则、AI 或房间时，至少做到：

1. 更新相应专题文档及必要测试。
2. 本地 `npm test` 全部通过。
3. PR 通过 GitHub Actions 的 Node.js 20/22 任务。
4. 手动核对公开状态不会暴露他人的隐藏手牌。
5. 修改触控或布局后，验证 PC、手机横屏与竖屏操作。
6. 新增公网能力时，记录真实设备、网络环境及异常恢复结果。

**当前定位：部署候选版，不代表已获得独立安全审计或真实公网可用性认证。**
