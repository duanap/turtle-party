# Debian / Nginx 部署与日常运维

**适用版本：** v0.3.0。当前仅提供参考流程和配置模板，**尚未在目标公网服务器完成正式验收**。

## 1. 运行条件

- Linux / Debian 13 或其他受支持系统；**Node.js 20+**。
- 单个 Node.js 进程运行一个游戏服务。
- 部署公网时使用有效 HTTPS 证书、Nginx 反向代理和受限制的运行用户。
- 无需数据库、Docker 和第三方 npm 依赖。

## 2. 本地启动

```bash
node --version
npm start
curl -fsS http://127.0.0.1:3000/api/health
npm test
```

默认绑定到 `127.0.0.1:3000`。切勿为了方便而直接向公网开放 3000 端口。

## 3. 推荐目录与权限

参考现有模板 `deploy/chou-wugui.service`：

- 项目源码：`/opt/chou-wugui/`。
- 专用系统用户：`wugui`（不使用 root 运行游戏）。
- 私有持久化目录：`/var/lib/chou-wugui/`，目录权限建议 `0700`。
- 状态文件：`/var/lib/chou-wugui/rooms.json`，文件权限 `0600`。
- systemd 环境变量：`HOST=127.0.0.1`、`PORT=3000`、`DATA_DIR=/var/lib/chou-wugui`、`TRUST_PROXY=1`。

启动服务前检查 systemd 模板的 `ExecStart` 指向真实存在且目标服务用户可执行的 Node.js 20+ 二进制文件。

## 4. systemd 服务

根据模板复制并检查配置后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now chou-wugui
sudo systemctl status chou-wugui
sudo journalctl -u chou-wugui -n 100 --no-pager
```

模板包含重启策略、工作目录、资源限制与基本沙箱约束。不要直接覆盖服务器已有同名服务而不检查现有配置。

## 5. Nginx HTTPS + SSE 代理

参考 `deploy/nginx-example.conf`：

- 将 `game.example.com`、证书路径替换为真实值。
- 代理转发到 `http://127.0.0.1:3000`。
- SSE 使用 `proxy_buffering off`、`proxy_cache off` 及足够长的 `proxy_read_timeout`。
- 代理转发 `Authorization` 请求头；不要将 token 写入 URL。
- 开启 HTTPS，HTTP 可 301 跳转；外部防火墙不开放 3000。
- 如果使用宝塔已有站点，**整合 location 到现有 HTTPS 虚拟主机**，避免重复配置一个 443 端口 server 块。

应用前执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -fsS https://game.example.com/api/health
```

上例域名为占位符。需要先准备真实证书和域名解析。

## 6. 备份与异常恢复

1. 备份私有 `rooms.json` 及所在目录时，**不要复制到公开静态目录**或提交 Git。
2. 最稳妥的备份方式是短暂停止服务后复制快照；若使用文件系统快照，也应保证一致性。
3. 恢复时先停止当前 Node 进程，检查目标目录权限，再替换数据；**不要两个实例同时写一份快照**。
4. 损坏快照会令服务拒绝启动；应检查日志并从可靠备份恢复，**不要直接删除快照以绕过错误**。
5. 重新部署不一定保留前端会话连续性；要验证同一凭证能恢复原座位及游戏进度。

## 7. 公网开放前检查

- [ ] 只暴露 80/443，Node 只绑定回环地址。
- [ ] 有效 TLS、禁止混合内容，Nginx SSE 实时转发正常。
- [ ] 专用低权限用户运行，快照/备份访问权限正确。
- [ ] 不在日志和 URL 中暴露会话 token。
- [ ] 对接备份、监控、限流与防火墙；根据需要配置 WAF。
- [ ] 完成 Android/iOS、网络切换、长时间连接和并发测试。
