# 抽乌龟 · 游戏规则

**适用版本：** 龟牌派对 v0.4.0 · 公开亮牌规则

## 1. 游戏概况

- **人数：** 2～6 人（快速开始默认 4 人）。
- **牌组：** 标准 52 张扑克牌，去掉大小王。
- **核心目标：** 抽走其他玩家的牌，凑成相同点数的对子并弃掉；最后持有一张无法配对的“乌龟牌”的玩家失败，其余玩家胜利。
- **没有牌型大小和下注。** 花色只用于区分具体牌，不决定配对或输赢。

## 2. 发牌与初始配对

1. 服务端将 52 张牌洗混，**随机移除 1 张并对所有玩家保密**，该局实际发 51 张。
2. 51 张牌按座位轮流发完，人数不能整除时允许手牌张数不同。
3. 系统对每个玩家手牌中**点数相同的两张牌**自动配成对子，不论花色。
4. 所有组成的对子公开进入弃牌区。一次最多两张配一对：同点数四张则组成两对；三张则先弃一对、剩一张。
5. 初始配对结束后，系统随机选出一名仍持牌的玩家先行动；已清空手牌的玩家安全脱身。

例如，`♠7 + ♥7` 可以配对；`♣9 + ♦Q` 不能配对。

## 3. 抽牌顺序

- **行动顺序：** 按固定座位顺时针轮流进行。
- **抽牌对象：** 从当前玩家**逆时针方向最近的一名仍持牌玩家**手中抽一张牌；已脱身者自动跳过。
- **每回合限抽一张，**成功配对不额外获得回合。
- 被抽玩家仅展示外观相同的背面手牌，抽牌人不能提前看到正面。
- 无论目标剩几张牌，都先选择再确认。选择会同步到全桌，被抽者手中对应的牌提起；可以改选或取消，选牌阶段不公开牌面。
- 确认后，抽到的牌向所有玩家翻开，再移入抽牌者手牌。系统立即裁决配对，界面按顺序展示移牌与配对消除；未配对的牌留在手中。
- 亮牌展示默认约 2.4 秒；下一回合的 30 秒操作时间在展示结束后开始，电脑也会等待展示结束再行动。

## 4. 手牌操作与锁定

- 玩家可以重排自己的手牌，也可以使用“洗序”打乱排列。
- **一旦成为当前回合的被抽牌对象，手牌位置立即锁定。** 对方完成抽牌后才能继续调整。
- 重排或洗序仅改变顺序，不换牌、不改点数、不重新发牌，不能用于逃避抽取。
- 其他玩家知道发生了重排，但**不知道调整后的具体牌面与位置映射**。
- 服务器以操作到达与回合状态为准，拒绝已经锁定的重排操作。

具体 PC / 手机操作见[《抽牌交互与界面》](抽牌交互与界面.md)。

## 5. 脱身与胜负

任一玩家手牌清零即安全脱身，不再抽牌或被抽牌，但可继续观看。

游戏最终**必须形成 25 对弃牌（50 张）并仅剩 1 张手牌**。这最后一张就是乌龟牌；持有它的玩家失败，其他玩家获胜。开局移除的牌与最终乌龟牌**点数相同、花色不同**，只在结算时揭晓。

**特殊残局：** 当三人及以上仍有手牌时，两名各剩一张的玩家可能在一次抽牌后凑成对子、**同时脱身**，其他玩家独自留下乌龟牌。该情况属于合法结算。

**双人残局：** 两名持牌玩家继续交替抽牌，不添加额外回合、道具或改变输赢规则。

## 6. 超时、掉线与再来一局

- 默认每次抽牌回合限时 **30 秒**，超时由服务端从合法背面牌位中随机代抽一张。
- 真人掉线后仍保留原座位与手牌；短暂离线宽限期后由托管继续，重新连接可恢复操作。
- 最终结算后，房主可以发起再来一局：重新洗牌、随机移除一张并重新发牌。
- 原牌局的已弃牌和乌龟牌**不参与下一局**。

房间、身份与断线行为详见[《大厅与房间》](大厅与房间.md)。

## 7. 公平边界

- 服务器控制随机洗牌、移除牌、发牌、配对与结算；真人客户端不能自选抽到的牌面。
- 每个玩家可以看到自己的手牌、每次抽到的公开牌面、公开对子以及牌数和回合信息；其余未公开手牌仍保密。
- 牌背样式和可点击区域必须统一，不得通过视觉差异泄漏暗牌。
- AI 不能读取其他人隐藏手牌或开局移除牌。参阅[《AI 策略与信息公平》](AI策略与信息公平.md)。

**实现依据：** `server/engine.js` 中的 `startGame`、`discardPairs`、`drawCard`、`finishIfNeeded`。
