# Turtle Party 技术架构

**适用版本：** v0.4.0。项目坚持**轻量单体架构**：无数据库、Docker、第三方 npm 运行依赖。

## 1. 技术栈

| 层级 | 组成 |
| --- | --- |
| 前端 | 原生 HTML5、CSS3、JavaScript ES Modules |
| 布局 | `public/style.css`（公共/PC）、`public/mobile.css`（手机/低高度横屏） |
| 后端 | Node.js 20+ 原生 `node:http` |
| 联机 | HTTP JSON 请求 + SSE 状态推送 |
| AI / 规则 | 服务端原生 JavaScript，脱敏观察输入 |
| 身份 | 随机 Bearer token，服务器仅保存 SHA-256 哈希 |
| 数据 | 进程内存 `Map` + 本机私有原子 JSON 快照 |
| 测试 | Node.js 原生 `node --test` |
| 运维 | systemd（可选）+ Nginx HTTPS 反向代理（可选） |

## 2. 目录职责

```text
public/
  index.html       页面入口
  app.js           UI、抽牌交互、会话、弱网重连与状态同步
  style.css        公共样式 / PC
  mobile.css       手机端、低高度横屏
server/
  index.js         HTTP API、房间、身份、限流、SSE、托管与定时器
  engine.js        发牌、配对、抽牌、结算、公平 AI
  store.js         私有快照序列化、验证、原子读写
  rate-limit.js    内存限流
tests/
  api.test.js / engine.test.js / store.test.js / ui.test.js
deploy/
  chou-wugui.service / nginx-example.conf
docs/
  规则、交互、AI、联机、部署与验收
```

## 3. 数据流与可信边界

```text
浏览器（自己的手牌 + 公开状态）
      │ HTTP POST：动作 + requestId + Bearer 凭证
      ▼
Node.js HTTP API → 会话/房间/回合校验 → 游戏规则引擎
      │                                  │
      │                           公平 AI 观察与决策
      │                                  │
      ├── 更新房间内存 Map ────────────────┘
      ├── 写入私有 rooms.json 快照
      └── 按玩家过滤状态，通过 SSE 推送 / HTTP 轮询
```

**服务端是唯一的规则裁决者。** 浏览器提交的只是目标背面牌位或动作请求，不能决定具体牌面、配对和胜负。

## 4. 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康状态 |
| `POST` | `/api/quick` | 快速 AI 开局 |
| `POST` | `/api/rooms` | 创建房间 |
| `POST` | `/api/join` | 加入等待房间 |
| `GET` | `/api/rooms/:code/state` | 拉取授权玩家的房间视图 |
| `GET` | `/api/rooms/:code/events` | SSE 实时更新 |
| `POST` | `/api/rooms/:code/action` | 抽牌、洗序、重排、补 AI、开局、离开等 |

需要授权的接口通过请求头 `Authorization: Bearer <token>` 认证，**不把 token 放在 URL 查询参数中**。操作包含请求 ID，服务端保存最近操作的指纹以去重。

## 5. 快照与恢复

默认目录 `data/` 不放在 `public/` 下；快照文件 `data/rooms.json` 使用原子替换和约束校验，文件权限目标为 `0600`。

快照包含房间、玩家、手牌、配对、剩余牌、回合、AI 合法记忆和近期操作记录。恢复时验证牌组完整性；损坏快照会导致**拒绝启动**，不会悄悄清空房间。

**限制：** 仅适用于一个 Node 进程；后台 AI 事件可能有约 70 ms 的合并写入窗口，而已确认真人操作在返回前等待写入。多进程共用同一快照会有冲突风险。

## 6. 环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Node 监听地址 |
| `PORT` | `3000` | HTTP 端口 |
| `DATA_DIR` | 项目根目录 `data` | 私有快照目录 |
| `TRUST_PROXY` | `0` | **只在可信本机 Nginx 后**设为 `1` |
| `TURN_MS` | `30000` | 回合操作时限（毫秒） |
| `DRAW_ANIMATION_MS` | `2400` | 抽牌展示窗口（毫秒），结束后再允许下一次抽牌；自动测试可设为 `0` |
| `DISCONNECT_GRACE_MS` | `5000` | 断线托管宽限（毫秒） |
| `MAX_ROOMS` | `300` | 单进程房间上限配置 |
| `MAX_STREAMS` | `300` | 单进程 SSE 流上限配置 |

上限是**配置阈值而非已经压测确认的可承载容量**。生产环境使用 systemd `Environment=` 或环境变量传参，不使用 `.env` 解析器。

## 7. 安全与现阶段边界

已包含同源检查、基础 CSP/响应头、限流、请求体大小限制、身份哈希和玩家私有视图隔离；不代表替代 HTTPS、备份、WAF、防火墙或独立安全审计。尚未完成真实公网与高并发负载验证。
